# 04 品控经营看板：设计说明与 Power BI / Tableau / SmartBI 搭建指南

> 术语与口径以 [00_术语与口径.md](00_术语与口径.md) 为准。本文每一节的结构相同：**结论 → 依据 → 做法**。

- 交互看板（HTML）：`dashboard/index.html`（本地双击即可打开，数据内嵌）
- BI 工具导入数据：`dashboard/bi_data/*.csv`（与 HTML 看板同源，均来自 ADS 层）

## 1. 需求拆解

**结论**：看板先回答"好不好"，再回答"在哪里"，最后给要落地动作的人看明细。

**依据**：不同使用方打开看板要回答的问题不同。

| 使用方 | 要回答的问题 | 看板上的位置 |
|---|---|---|
| 品控负责人 | 这个月品质好不好？比上期好还是差？ | 第一行指标卡：品质客诉率（核心指标，带控制图状态和上期对比） |
| 品控运营 | 问题出在哪个标签？ | 结果指标 · 本期 vs 上期 |
| 类目运营 | 哪个一级类目、哪个主品类变差？ | 一级类目排行（点击联动）+ 主品类明细表 |
| 仓配 / 履约 | 多件订单是不是少件漏发集中的地方？ | 订单结构图 |
| 商家管理 | 哪些商家要整改？ | 商家分层页：散点图 + 商家明细 |
| 所有人 | 这个数怎么算的？ | 指标口径页（指标字典与六条口径规则） |

**做法**：三页结构：经营总览 → 商家分层 → 指标口径。

## 2. 呈现逻辑

**结论**：总 → 分 → 明细；预警清单放在第一屏。

**依据**：第一屏只放 5 张指标卡，品质客诉率单独放大，下面紧跟预警清单；第二屏回答"是什么问题、在哪里"；第三屏是能排序的明细表。预警清单的三条规则都有对应的 SQL 题，口径相同：

| 预警 | 规则 | 对应 SQL | 受哪些筛选影响 |
|---|---|---|---|
| 控制图越限的月份 | 当月品质客诉率高于上控制限（中心线 = 当前筛选下 2017 年的品质客诉率，控制限 = 中心线 ± 3 × √（中心线 × (1 − 中心线) ÷ 当月签收订单数）） | —（与控制图同一套计算） | 时间、一级类目、订单结构 |
| 品质客诉率连续 3 个月上升的主品类 | 连续 4 个自然月每月签收订单 ≥ 30，品质客诉率（保留 4 位小数）逐月上升 | Q07（题库按订单 × 品类归属；看板按主品类归属，个别品类结果会不同） | 时间、一级类目、订单结构 |
| 按评价日期连续 3 天及以上有品质客诉订单的商家 | 同一商家连续 3 天及以上每天都有品质客诉订单 | Q15（全量结果同为 51 条） | 只受时间（按连续区间的最后一天） |

**做法**：点主品类名会把一级类目筛选切到该类目；点商家 ID 会跳到商家分层页并搜索该商家。

**设计取舍**：

| 取舍 | 原因 |
|---|---|
| 差评率不和品质客诉率放在同一张双轴图里 | 两个指标量纲不同，双轴的对齐是任意的，会制造假相关；改为各自的指标卡 |
| 结果指标用本期 vs 上期对比条形，而不是堆叠面积 | 一个订单可命中多个标签，堆叠会让各层相加大于品质客诉率 |
| 假货客诉率单独放在指标卡里 | 它以"单/万单"表示，和其他结果指标（百分比）放在同一个坐标轴上会误导 |
| 一级类目排行只用一种颜色，选中的高亮、其他置灰 | 颜色只表示"是否选中"，不重复表示数值大小 |
| 状态用"圆点 + 文字"（越限 / 高于中心线 / 不高于中心线） | 不只靠颜色区分，色弱用户和黑白打印也能读 |
| 每张图都有"表格"切换 | 图表负责趋势和对比，精确数值随时可查 |
| 筛选器只有一行，作用于整个总览页 | 避免"每张图各有各的筛选"导致数字对不上；商家分层页使用固定的商家评估窗口，页面上注明"不受顶部筛选影响" |
| 所有比率在筛选之后才计算 | 汇总表只存订单数，筛选后再相除，不对比率求平均 |
| 上期取"紧邻的等长上期" | 选 6 个月就和前 6 个月比；前面不够长时显示"无可比上期" |

## 3. 数据模型

**结论**：HTML 看板和 BI 工具用同一份 ADS 数据集。

**依据**：

```
ads_qc_dashboard_cube   粒度：下单月 × 一级类目 × 主品类 × 订单结构（2,865 行，全部是可相加的订单数）
ads_seller_scorecard    粒度：商家（商家评估窗口 2018-03 至 2018-08 的 299 家参评商家）
ads_qc_kpi_month        粒度：下单月（月度核心指标，用于对账）
dim_category            品类维表（葡 / 英 / 中 / 一级类目）
```

**做法**：Power BI 用星型模型。

```
                dim_date（日历表）
                     │ 1:N  (date = month_start)
dim_category ──1:N── ads_qc_dashboard_cube ──N:1── dim_order_type

ads_seller_scorecard （独立，不与 cube 建关系）
```

> 如果 BI 工具能直连 MySQL，也可以直接用订单宽表 `dwd_qc_order`（约 10 万行）做事实表，下钻到单个订单。

```powerquery
// ads_qc_dashboard_cube：把 "2018-03" 转成日期，供日历表关联
= Table.AddColumn(源, "month_start", each Date.FromText([purchase_month] & "-01"), type date)
```

```dax
dim_date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2017, 1, 1 ), DATE ( 2018, 8, 31 ) ),
    "下单月", FORMAT ( [Date], "yyyy-mm" ),
    "年", YEAR ( [Date] ),
    "季度", "Q" & QUARTER ( [Date] )
)
-- 标记为日期表；关系：dim_date[Date] 1 → N cube[month_start]
```

## 4. DAX 度量值（名称与指标字典一致）

**结论**：度量值一律"先求和再相除"，名称与指标字典的指标名称相同。

**做法**：

```dax
签收订单数          = SUM ( cube[delivered_cnt] )
品质客诉订单数      = SUM ( cube[qc_cnt] )

-- QC001 核心指标
品质客诉率          = DIVIDE ( [品质客诉订单数], [签收订单数] )

-- QC101 ~ QC105 结果指标（一个订单可命中多个标签：不要相加）
少件漏发客诉率      = DIVIDE ( SUM ( cube[qc_missing_cnt] ),  [签收订单数] )
质量缺陷客诉率      = DIVIDE ( SUM ( cube[qc_defect_cnt] ),   [签收订单数] )
货不对板客诉率      = DIVIDE ( SUM ( cube[qc_mismatch_cnt] ), [签收订单数] )
假货客诉率_单每万单 = DIVIDE ( SUM ( cube[qc_fake_cnt] ),     [签收订单数] ) * 10000
包装破损客诉率      = DIVIDE ( SUM ( cube[qc_package_cnt] ),  [签收订单数] )

-- EX201 / FF501 / FF502
差评率              = DIVIDE ( SUM ( cube[bad_cnt] ), SUM ( cube[review_cnt] ) )
准时签收率          = 1 - DIVIDE ( SUM ( cube[late_cnt] ), [签收订单数] )
平均送达时长        = DIVIDE ( SUM ( cube[delivery_days_sum] ), SUM ( cube[delivery_days_cnt] ) )

-- 紧邻的等长上期（选 3 个月就对比前 3 个月）
品质客诉率_上期 =
VAR MinD = MIN ( dim_date[Date] )
VAR MaxD = MAX ( dim_date[Date] )
VAR N    = DATEDIFF ( MinD, MaxD, MONTH ) + 1
RETURN
    CALCULATE ( [品质客诉率], DATESINPERIOD ( dim_date[Date], MinD - 1, -N, MONTH ) )

品质客诉率_较上期_pp = ( [品质客诉率] - [品质客诉率_上期] ) * 100

-- 控制图：中心线 = 当前筛选下 2017 年的品质客诉率
中心线 =
CALCULATE ( [品质客诉率], REMOVEFILTERS ( dim_date ), dim_date[年] = 2017 )

上控制限 = [中心线] + 3 * SQRT ( [中心线] * ( 1 - [中心线] ) / [签收订单数] )

-- 状态标识（指标卡 / 表格条件格式用）
品质状态 =
SWITCH ( TRUE (),
    ISBLANK ( [品质客诉率] ),        BLANK (),
    [品质客诉率] > [上控制限],       "● 越限",
    [品质客诉率] > [中心线],         "● 高于中心线",
                                     "● 不高于中心线" )

品质状态色 =
SWITCH ( TRUE (),
    [品质客诉率] > [上控制限], "#B8005A",
    [品质客诉率] > [中心线],   "#8A5A00",
                               "#1F6B40" )

-- 主品类明细：签收订单 ≥ 30 才展示（视觉级筛选器：该度量 = 1）
样本量足够 = IF ( [签收订单数] >= 30, 1, 0 )
```

**两个常见坑**：

1. 不要在表格里对"品质客诉率"列用"平均值"汇总：总计行会变成各行比率的简单平均。上面的度量值先求和再相除，总计行自动正确。
2. `品质客诉率_上期` 依赖连续的日期表；如果直接用文本月份 `purchase_month` 做轴，时间智能函数不会生效。

## 5. 页面搭建步骤（Power BI）

| 页面 | 视觉对象 | 字段 / 设置 |
|---|---|---|
| 经营总览 | 切片器 ×3 | dim_date[下单月]（区间）、dim_category[一级类目]、cube[order_type]（单件订单 / 多件订单分组） |
| | 卡片 ×5 | 品质客诉率（放大）、差评率、准时签收率、假货客诉率_单每万单、签收订单数；副标题放 `品质客诉率_较上期_pp` |
| | 折线图 | X：dim_date[下单月]；Y：品质客诉率、中心线、上控制限 |
| | 簇状条形图 | 结果指标：用"字段参数"把 4 个百分比形式的结果指标做成一个轴；图例：本期 / 上期 |
| | 条形图 | Y：一级类目；X：品质客诉率；开启"交叉筛选" |
| | 堆积条形图 | Y：order_type；X：少件漏发客诉率 + (品质客诉率 − 少件漏发客诉率) |
| | 表 | 主品类、签收订单数、各结果指标、品质状态；条件格式 → 字体颜色 → 按字段值 `品质状态色` |
| 商家分层 | 散点图 | X：delivered_cnt（商家签收订单数，对数轴）；Y：qc_rate_smooth（平滑品质客诉率）；图例：risk_level（商家分层） |
| | 表 | ads_seller_scorecard 全部字段，默认筛选 risk_level = 高风险 |
| 指标口径 | 表 / 文本框 | 导入 `docs/品控指标字典.xlsx` 的"指标体系"工作表 |

**钻取**：在主品类明细表上设置钻取页（按主品类），钻取页展示该主品类的月度趋势和主商家列表。

## 6. Tableau 计算字段

```
// 同样坚持"先求和再相除"
[品质客诉率]          = SUM([qc_cnt]) / SUM([delivered_cnt])
[差评率]              = SUM([bad_cnt]) / SUM([review_cnt])
[准时签收率]          = 1 - SUM([late_cnt]) / SUM([delivered_cnt])
[假货客诉率_单每万单] = SUM([qc_fake_cnt]) / SUM([delivered_cnt]) * 10000
[订单结构分组]        = IF [order_type] = '单件' THEN '单件订单' ELSEIF [order_type] = '无商品明细' THEN '无商品明细' ELSE '多件订单' END

// 环比：表计算，沿"下单月"计算
[品质客诉率_较上月pp] = ([品质客诉率] - LOOKUP([品质客诉率], -1)) * 100
```

Tableau Public 的逐步操作见 [07_Tableau_Public搭建清单.md](07_Tableau_Public搭建清单.md)。

## 7. SmartBI 说明

SmartBI 的做法与 Power BI 类似：把 `ads_qc_dashboard_cube` 建成数据集，在数据集里把上述指标定义为计算度量（写成 `SUM(qc_cnt)/SUM(delivered_cnt)` 这种"先求和再相除"的形式），在仪表盘里用"参数 + 筛选器"做下单月区间和一级类目联动，用条件格式给主品类明细加状态色。口径统一维护在数据集层，报表层不写口径，保证不同报表同一指标数值一致。

## 8. 上线前核对清单

- [ ] 看板"品质客诉率"与 `ads_qc_kpi_month.qc_rate` 逐月一致（`scripts/07_data_quality_check.py` 已校验 cube 与月度核心指标表的合计一致）
- [ ] 去掉"签收订单 ≥ 30"的门槛后，主品类明细的签收订单数合计 = 指标卡的签收订单数（没有商品明细的订单不是签收订单，不影响）
- [ ] 5 个结果指标之和 ≥ 品质客诉率（一个订单可命中多个标签；出现"小于"说明口径出错）
- [ ] 最近一个月的送达时长偏低，是因为还没签收的订单没有进入分母，看板上需加注释
