## 1. 需求拆解：谁看、看什么、看完做什么

| 使用方 | 打开看板要回答的问题 | 看板上的位置 |
|---|---|---|
| 品控负责人 | 这个月品质好不好？比上期好还是差？ | KPI 首行：品质客诉率（北极星，带状态标识和环比） |
| 品控运营 | 问题出在哪一类？（少件 / 缺陷 / 货不对板 / 假货） | 问题类型 · 本期 vs 上期 |
| 类目运营 | 哪个类目、哪个品类在拖后腿？ | 一级类目排行（点击联动）+ 品类明细表 |
| 仓配 / 履约 | 多件订单是不是少件的重灾区？ | 订单结构图 |
| 商家管理 | 哪些商家该约谈、该限流？ | 商家风险页：散点 + 风险榜 |
| 所有人 | 这个数怎么算的？ | 指标口径页（指标字典落地到看板） |

## 2. 呈现逻辑

**总 → 分 → 明细。** 第一屏只放 5 张 KPI 卡片，品质客诉率单独放大（唯一的 hero 数字）；第二屏回答"是什么问题、在哪里"；第三屏是能排序的明细表，给要落地动作的人用。

**设计上的几个取舍（面试可讲）：**

| 取舍 | 原因 |
|---|---|
| 差评率不和品质客诉率放在同一张双轴图里 | 两个指标量纲不同，双轴的对齐是任意的，会制造假相关。改为各自的 KPI 卡 + 独立趋势 |
| "问题类型"用本期 vs 上期对比条形，而不是堆叠面积 | 问题类型是多标签，堆叠会让各层相加 > 总量，误导读者 |
| 类目排行只用一种颜色，被选中的类目高亮、其他置灰 | 颜色只编码"选中状态"，不重复编码数值大小 |
| 状态用"圆点 + 文字"（达标 / 关注 / 预警） | 不只靠颜色区分，色弱用户和黑白打印也能读 |
| 每张图都有"表格"切换 | 图表负责趋势和对比，精确数值随时可查 |
| 筛选器只有一行，作用于整个总览页 | 避免"每张图各有各的筛选"导致数字对不上；商家页用固定窗口，页面上明确标注"不受顶部筛选影响" |
| 所有比率在筛选之后才计算 | 看板底表只存计数（签收单、客诉单……），筛选后再相除，避免"比率再平均" |
| 环比取"紧邻的等长上期" | 选 6 个月就和前 6 个月比；前面不够长时显示"无可比上期"，而不是硬凑 |

## 3. 数据模型

HTML 看板和 BI 工具用的是同一份 ADS 数据集：

```
ads_qc_dashboard_cube   粒度：下单月 × 一级类目 × 品类 × 订单结构（2,865 行，全部为可加度量）
ads_seller_scorecard    粒度：商家（近 6 个月，签收 ≥ 30 单的 299 家）
ads_qc_kpi_month        粒度：月（平台 KPI，用于对账）
dim_category            品类维表（葡 / 英 / 中 / 一级类目）
```

Power BI 推荐星型模型：

```
                dim_date (日历表)
                     │ 1:N  (date = month_start)
dim_category ──1:N── ads_qc_dashboard_cube ──N:1── dim_order_type
                                              
ads_seller_scorecard （独立，不与 cube 建关系）
```

> 如果 BI 工具能直连 MySQL，也可以直接用订单粒度的宽表 `dwd_qc_order`（约 10 万行）做事实表，下钻到单个订单。

### Power Query 预处理

```powerquery
// ads_qc_dashboard_cube：把 "2018-03" 转成日期，供日历表关联
= Table.AddColumn(源, "month_start", each Date.FromText([purchase_month] & "-01"), type date)
```

```dax
dim_date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2017, 1, 1 ), DATE ( 2018, 8, 31 ) ),
    "月份", FORMAT ( [Date], "yyyy-mm" ),
    "年", YEAR ( [Date] ),
    "季度", "Q" & QUARTER ( [Date] )
)
-- 标记为日期表；关系：dim_date[Date] 1 → N cube[month_start]
```

## 4. DAX 度量值（与指标字典编码一一对应）

```dax
签收单            = SUM ( cube[delivered_cnt] )
品质客诉单        = SUM ( cube[qc_cnt] )

-- QC001 北极星
品质客诉率        = DIVIDE ( [品质客诉单], [签收单] )

-- QC101 ~ QC105 品质拆解（多标签：不要把它们相加）
少件漏发率        = DIVIDE ( SUM ( cube[qc_missing_cnt] ),  [签收单] )
质量缺陷率        = DIVIDE ( SUM ( cube[qc_defect_cnt] ),   [签收单] )
货不对板率        = DIVIDE ( SUM ( cube[qc_mismatch_cnt] ), [签收单] )
假货投诉_每万单   = DIVIDE ( SUM ( cube[qc_fake_cnt] ),     [签收单] ) * 10000
包装破损率        = DIVIDE ( SUM ( cube[qc_package_cnt] ),  [签收单] )

-- EX201 / FF501 / FF502
差评率            = DIVIDE ( SUM ( cube[bad_cnt] ), SUM ( cube[review_cnt] ) )
准时签收率        = 1 - DIVIDE ( SUM ( cube[late_cnt] ), [签收单] )
平均送达时长      = DIVIDE ( SUM ( cube[delivery_days_sum] ), SUM ( cube[delivery_days_cnt] ) )

-- 紧邻的等长上期（选 3 个月就对比前 3 个月）
品质客诉率_上期 =
VAR MinD = MIN ( dim_date[Date] )
VAR MaxD = MAX ( dim_date[Date] )
VAR N    = DATEDIFF ( MinD, MaxD, MONTH ) + 1
RETURN
    CALCULATE ( [品质客诉率], DATESINPERIOD ( dim_date[Date], MinD - 1, -N, MONTH ) )

品质客诉率_较上期_pp = ( [品质客诉率] - [品质客诉率_上期] ) * 100

-- 状态标识（卡片 / 表格条件格式用）
品质状态 =
SWITCH ( TRUE (),
    ISBLANK ( [品质客诉率] ),   BLANK (),
    [品质客诉率] <= 0.04,       "● 达标",
    [品质客诉率] <= 0.055,      "● 关注",
                                "● 预警" )

品质状态色 =
SWITCH ( TRUE (),
    [品质客诉率] <= 0.04,  "#006300",
    [品质客诉率] <= 0.055, "#8A5800",
                           "#B42323" )

-- 品类明细表：签收 ≥ 30 单才展示（视觉级筛选器：该度量 = 1）
样本量足够 = IF ( [签收单] >= 30, 1, 0 )
```

**两个常见坑：**

1. 不要在表格里对"品质客诉率"列用"平均值"汇总——总计行会变成各行比率的简单平均。上面的度量值是先求和再相除，总计行自动正确。
2. `品质客诉率_上期` 依赖连续的日期表；如果直接用文本月份 `purchase_month` 做轴，时间智能函数不会生效。

## 5. 页面搭建步骤（Power BI）

| 页面 | 视觉对象 | 字段 / 设置 |
|---|---|---|
| 经营总览 | 切片器 ×3 | dim_date[月份]（区间）、dim_category[一级类目]、cube[order_type]（单件 / 多件分组） |
| | 卡片 ×5 | 品质客诉率（放大）、差评率、准时签收率、假货投诉_每万单、签收单；副标题放 `品质客诉率_较上期_pp` |
| | 折线图 | X：dim_date[月份]；Y：品质客诉率；常量线 0.04（目标）、0.055（预警） |
| | 簇状条形图 | 问题类型：用"字段参数"把 5 个拆解度量做成一个轴；图例：本期 / 上期 |
| | 条形图 | Y：一级类目；X：品质客诉率；开启"交叉筛选" |
| | 堆积条形图 | Y：order_type；X：少件漏发率 + (品质客诉率 − 少件漏发率) |
| | 表 | 品类、签收单、各项率、品质状态；条件格式 → 字体颜色 → 按字段值 `品质状态色` |
| 商家风险 | 散点图 | X：delivered_cnt（对数轴）；Y：qc_rate_smooth；图例：risk_level |
| | 表 | ads_seller_scorecard 全字段，默认筛选 risk_level = 高风险 |
| 指标口径 | 表 / 文本框 | 导入 `docs/品控指标字典.xlsx` 的"指标体系" sheet |

**钻取：** 在"品类明细"表上设置钻取页（按品类），钻取页展示该品类的月度趋势 + 商家列表。

## 6. Tableau 计算字段

```
// 同样坚持"先求和再相除"
[品质客诉率]      = SUM([qc_cnt]) / SUM([delivered_cnt])
[差评率]          = SUM([bad_cnt]) / SUM([review_cnt])
[准时签收率]      = 1 - SUM([late_cnt]) / SUM([delivered_cnt])
[假货投诉_每万单] = SUM([qc_fake_cnt]) / SUM([delivered_cnt]) * 10000
[订单结构分组]    = IF [order_type] = '单件' THEN '单件' ELSEIF [order_type] = '无商品明细' THEN '无商品明细' ELSE '多件' END
[品质状态]        = IF [品质客诉率] <= 0.04 THEN '达标' ELSEIF [品质客诉率] <= 0.055 THEN '关注' ELSE '预警' END

// 环比：表计算，沿"月份"计算
[品质客诉率_环比pp] = ([品质客诉率] - LOOKUP([品质客诉率], -1)) * 100
```

## 7. SmartBI 说明

SmartBI 的做法与 Power BI 类似：把 `ads_qc_dashboard_cube` 建成**数据集**，在数据集里把上述指标定义为**计算度量**（写成 `SUM(qc_cnt)/SUM(delivered_cnt)` 这种"先聚合再相除"的形式），在**仪表盘**里用"参数 + 筛选器"做月份区间和类目联动，用"条件格式 / 预警"给品类明细表加状态色。指标口径统一维护在数据集层，报表层不写口径，保证不同报表同一指标数值一致。
